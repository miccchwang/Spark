# 在线版：把自己的后端接上去

Spark 默认是纯本地应用——不联网、不需要账号。在线版是**可选**的第二层：加通讯人、建群组、
把某一条灵感分享出去，并围绕它讨论。切换开关在 **设置 → 运行模式**，一个 APK 同时包含两种模式。

本地那一半完全不受影响：文字、拍照、录音、转写、提炼、待办都在本机，切换模式不会把已有内容搬走。

---

## 1. 建一个后端

只需要一个 [Supabase](https://supabase.com) 项目（免费档就够）。任何兼容 PostgREST 的
Postgres 也行，下面的步骤一样。

1. 新建项目，等它初始化完成。
2. 打开左侧 **SQL Editor**，新建查询。
3. 把仓库里的 [`supabase/schema.sql`](../supabase/schema.sql) **整个文件**粘进去，点 Run。

跑完会建好 7 张表和全部权限规则：

| 表 | 用途 |
| --- | --- |
| `profiles` | 账号的影子表，用来显示名字、按邮箱找人 |
| `contacts` | 你自己的通讯录，只有你能看到 |
| `groups` / `group_members` | 群组与成员 |
| `shared_ideas` | 被分享出去的灵感（**只有文字**） |
| `messages` | 讨论区的留言与命令 |
| `shared_todos` | 群里由 `/todo` 生成的待办 |

这个脚本可以重复执行，不会破坏已有数据。

4. 回到 **Project Settings → API**，记下两个值：
   - **Project URL**，形如 `https://abcdefgh.supabase.co`
   - **anon public** key，一长串 `eyJ...`

> anon key 是设计上就公开的，放进客户端没有问题。真正拦住别人的是脚本里建的
> **行级安全策略（RLS）**：每条数据都带着所有者或群组归属，别人查不到。
> **不要**关闭 RLS，也不要把 `service_role` key 填进 App。

---

## 2. 在 App 里接上

1. 打开 Spark → 右上角 **⋯** → **运行模式** 选 **在线**。
2. 填 **后端地址** 和 **Anon key**，点 **保存并连接**。
3. 填邮箱和密码，点 **注册**。
   - 如果 Supabase 开着邮箱确认（默认开着），会提示你去邮箱点确认链接，回来再 **登录**。
   - 想跳过确认：**Authentication → Providers → Email** 里关掉 *Confirm email*。
4. 登录后底部导航会多出一个 **社群** 入口。

## 3. 怎么用

### 通讯人

社群 → 通讯人 → **添加**，填对方的**注册邮箱**。对方必须已经在同一个后端上注册过。
添加只是记进你自己的通讯录，**不会**给对方任何权限。

### 群组

社群 → 群组 → **新建**，起个名字，从通讯人里勾选成员。只有群主能加人。

### 分享一条灵感

进入群组 → **分享灵感** → 选一条本机灵感 → 选群组 → **分享**。

> 只发**文字**：标题、备注，以及本机算出来的关键词。
> **录音文件和照片都留在设备上，不会上传。** 这也是为什么分享面板会明确写出「只发文字」。

同一个灵感可以分享到多个群，每个群有各自独立的讨论。重复分享到同一个群是刷新，不会报错。

### 讨论区

点开一条分享，就是这条想法的讨论区。可以发普通留言，也可以发 **斜杠命令**。

| 命令 | 作用 | 例子 |
| --- | --- | --- |
| `/todo` | 生成一条群待办 | `/todo 明天 换掉登录页的按钮色` |
| `/done` | 勾掉一条待办 | `/done 2` 或 `/done 换按钮色` |
| `/assign` | 指派给群里的人 | `/assign @li@team.com 周五 出配色稿` |
| `/tag` | 给这条灵感打标签 | `/tag 配色 动效` |
| `/pin` | 把结论钉在讨论最上面 | `/pin 结论：先统一按钮颜色` |
| `/summary` | 本机算一段摘要发出来 | `/summary 3` |
| `/keywords` | 本机列出最突出的词 | `/keywords 6` |
| `/help` | 列出全部命令 | `/help` |

细节：

- **时间**会被认出来，转成一个具体日期存下来。`明天`、`后天`、`下周五`、`3月25日`、
  `3天后`、`月底`、`tomorrow`、`next monday` 都行。写不写都可以。
- 输入 `/` 会弹出命令面板；输入命令后，输入框上方会显示这句话**将要做什么**，
  确认无误再发。
- `/assign` 里的 `@li` 会按群成员的邮箱或名字匹配。匹配不到会直接报错，不会静默失败。
- `/done 2` 里的序号就是讨论区下方待办清单的顺序。

### `/summary` 和 `/keywords` 不调用任何模型

这两个命令跑的是和「提炼要点」完全相同的**本机确定性算法**——词频 × 逆文档频率 ×
句子权重，没有模型、没有联网。同样的输入永远得到同样的输出，它不会替你「理解」或改写。

它只做两件事，都在本地：

- **关键词**：ICU 分词 ∪ 中文二元组。ICU 会把「动效」拆成「动/效」，二元组不会漏掉它；
  而「页的」这类碎片到处出现，会被 IDF 压下去。
- **摘要**：把句子当成节点、句子相似度当成边，跑 TextRank 挑出中心句，再按原顺序放回。

在讨论区里，IDF 只用两份文档算：**灵感原文** 和 **讨论内容**。在两份里都出现的词是已知
背景，只在讨论里出现的词才是新信息——这正是你回头补看一条讨论时想先看到的东西。

## 4. 已知边界

- **不做实时推送。** 别人发的消息需要重新打开讨论或切回群组才能看到（关闭讨论区时会自动刷新）。
  `schema.sql` 末尾把 `messages` 和 `shared_todos` 加进了 `supabase_realtime` 发布，
  以后想接实时订阅不用改表结构。
- **命令的效果和留言不是一次事务。** REST 没有跨表事务，所以 `/todo` 会先建待办、再发留言。
  如果留言失败，待办仍然存在——看得见的多一条，好过静默少一条。
- **录音和照片都不上传。** 只有文字会进后端。这是刻意的，不是待办事项。
- **本地缓存。** 读过的讨论会存在本机，没网时仍能翻看（会标注「本机缓存」），但发不出去。

## 5. 自检

```bash
# 语法
for f in www/js/*.js; do node --check "$f"; done

# 真实 Chrome 端到端（本地模式 + 在线模式，含命令解析）
node /tmp/spark-e2e.js
```

端到端脚本用一个内存里的假后端替换 `window.Api`，所以不需要真的连 Supabase 就能跑完
通讯人 → 群组 → 分享 → 讨论 → 命令的全流程。
